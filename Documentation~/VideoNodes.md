# 视频节点扩展

Unity 编译完成后，打开现有 Node Composer 图，通过“添加节点 → 影视 → 视频播放”创建节点；画布右键“配置节点 → 影视 → 视频播放”同样可用。

选中节点，在属性面板填写视频地址和音量（0～1）。进入端口接受控制连接，播放完成和播放失败端口各最多连接一个后继节点。可将后继连回前面的节点，构成环路。

## 视频画面与拖拽

从 Project 窗口拖一个 VideoClip 到视频节点的画面区域，或在属性面板的“视频资源”选择视频。配置保存资源路径 source 与 assetGuid，后者用于编辑器在资源移动后继续定位视频；运行时资源加载器需按业务资源映射处理这些标识，不能直接调用 AssetDatabase。

选中视频节点后准备真实视频画面，节点上提供静音播放／暂停和帧位置拖动。其他已预览节点显示缓存画面；首次预览需选中节点。最多一个选中节点解码，缓存最多 16 个视频画面；切换选中、关闭窗口、撤销、域重载和切换播放模式会清理预览会话。URL 只保存配置，不自动联网生成画面。

## 多个帧输出端口与 UI 节点

1. 选中视频节点，在属性面板“帧输出端口”点击“添加帧端口”，填写从 0 开始的帧数。可添加多个，例如 120、360、800；也可以定位预览后点击“添加当前预览帧”。
2. 添加节点 → 影视 → 交互 UI，在属性面板“影视 UI 类”选择继承 `Game.Framework.UI.MovieUIForm` 的具体 UI 类。该基类继承 UGUI，类编译后自动出现在列表中。
3. 参数填写 JSON 对象并点击“应用参数”，例如 `{"text":"请选择","options":["开门","离开"]}`。非法输入不会覆盖已保存参数，未点击应用的文本不会导出。
4. 在 UI 节点设置“打开时暂停来源视频”，默认不暂停。
5. 将视频节点“第 120 帧”等输出连接到 UI 节点“打开”。一个视频可有多个帧端口，同一帧也可连多个 UI。

帧端口 ID 为 frame:<帧数>，帧列表保存在视频的 frames 属性，不额外增加交互标记 ID。修改或删除帧会删除对应旧端口的连线，其他帧连线不受影响，整个修改可 Undo/Redo。帧数不能为负、重复或小数；已解析的视频会提示超出视频长度的触发帧。

UI 节点的分支输出可连接后续节点。预期业务规则为：无后继时结束该 UI 并解除其暂停；后继是 UI 时继续 UI 流程并保留视频；后继是视频时切换视频。程序性销毁／取消不能冒充交互完成。以上为业务驱动约定，当前编辑器仅保存连线与配置，预览不会打开 UI 或执行暂停策略。

可导入 Samples~/GraphExamples/video-ui.json 体验两个不同帧端口和两个独立 UI；示例的 UI 类型为占位值，需在列表中重新选择项目实际的影视 UI 类。示例引用随测试提供的 2 秒红／蓝色视频，可替换为自己的视频。

使用现有工具栏“导入配置 JSON／导出配置 JSON”保存配置。示例见 Samples~/GraphExamples/video-cycle.json，视频 source 使用 movecomponent-preview 资源键，运行时绑定到自己的 VideoClip。编辑期间允许空地址；音量范围与地址可播放性由后续业务加载器检查，当前编辑器只校验属性数据类型。

本扩展提供配置编辑和画面预览，预览不执行图流程或业务 UI。业务运行时使用相同节点定义注册到独立注册表，再使用 GraphJsonCodec 读取配置：

```csharp
var registry = NodeDefinitionRegistry.CreateDefault();
new VideoNodeExtension().Register(registry);
var result = new GraphJsonCodec(registry).Decode(json);
```

命名空间为 GameFrameX.NodeComposer 与 GameFrameX.NodeComposer.Video。每个注册表只注册一次；重复注册会报错。

## 验证

本次 UI 分支功能完成了实际 Unity EditMode 验证，包含分支 JSON、路由、基类会话、端口编辑与撤销/重做。Tests/Editor/VideoNodes 为协议测试，Tests/Editor/VideoNodesIntegration 为实际 Unity 图、Undo、资源引用和预览测试；该目录中的 Fixtures/preview.mp4 为自动生成的红／蓝色视频，不含业务素材。

## 图节点与业务状态

视频节点和 UI 节点是独立配置单元，不表示同级运行状态。视频帧连线触发 UI 时，业务主流程保留当前视频状态，并把 UI 作为该次视频播放的附属交互；UI 的 pauseVideo 只控制来源播放器暂停，不停止流程更新。UI 完成后由选中分支的连线决定结束交互、打开另一 UI，或请求切换主视频。该归属由运行时触发路径确定，节点坐标和图布局不参与判断；JSON 格式不变。

UI 配置使用 `uiType`（`命名空间.类名, 程序集简单名称`），替代原 `uiId`。缺失或不再继承影视基类的类型会显示错误并保留原值，避免导入时悄悄替换。运行时 UI 请求提供解析后的 `Type`。旧 UI ID 配置需要重新选择类后导出。

已有原生 `.asset` 编辑图：选中任一 UI 节点，点击“升级此图的旧 UI 配置”，再重新选择影视 UI 类。升级保留参数与连线，支持 Undo。旧版导出 JSON 如含 `uiId`，需先将该字段替换为 `"uiType": ""` 再导入重选，业务加载器不接受旧 ID。

类型列表排除仅在 Editor 中编译的程序集和测试程序集。UI 类若放在独立 asmdef 中，该 asmdef 需要引用 `Game.Framework.MovieUI`。

## UI 分支端口

选中 UI 节点，在“分支输出端口”中点击“添加分支”，编辑名称，用 ↑ / ↓ 调整顺序，用“删除”移除。分支 ID 自动生成，改名和排序不改变 ID 或连线；删除分支会移除对应连线，支持编辑图撤销。每个输出最多连接一个后继，可以是视频或 UI。

打开 UI 时按列表顺序传入所有分支，包括没有连线的分支。UI 提交没有连线的分支只结束当前交互，并释放它对来源视频的暂停。分支名称不是 UI 必须展示的选项文字，内容仍由传入参数控制。

JSON 使用 `branches: [{"id":"稳定ID","name":"分支名称"}]`，动态控制端口为 `branch:<id>`。显式空数组没有输出分支，UI 只能取消。缺少 branches 或为 null 的旧配置仍提供“交互完成”分支；修改列表时保留该分支的 `completed` ID 和端口，原连线不会丢失。新添加的分支使用自动生成的 ID。

示例 `Samples~/GraphExamples/video-ui.json` 包含选项 UI 的两个分支，分别连接两个视频。UI 类型是占位值，需要选择实际 UI 类。

## 连接数据与逻辑节点

数据菜单中的文本、数值、布尔、整数节点同时承担流程值功能。设置初始值后，从“当前值”数据输出连接到流程菜单中对应类型的条件或修改节点。条件配置比较运算并连接左右值；修改节点从下拉框选择目标数据节点，连接操作值，并选择赋值/增加/减少（按类型支持）。数据线负责取值，白色控制线决定何时判断或修改。

视频指定帧可以连接条件节点，再由成立/不成立连接 UI 或视频；UI 的分支也可以先修改数据再转视频。相同视频节点重新进入会从头播放，当前流程值保留；重新启动整个流程才恢复初始值。工具只编辑与导出，运行语义由 Runtime/VideoFlow 实现。
